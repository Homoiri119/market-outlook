# 寄り付き予想の要因分析(2026-10-14)

計算:`py reports/factor_review.py` → [factor_review_results.json](factor_review_results.json)
対象:日経平均の寄り付きギャップ(当日始値 ÷ 前日終値 − 1)、2021-01〜2026-10 の **1,409営業日**。
要因は「前日の東京引け〜当日の寄りまで」に終わった米国側の動き(先物は前日東京終値比)。

## 1. 今の予想の仕組み

```
予想寄り = 0.7 × 日経先物ギャップ + 0.3 × 回帰モデル(S&P500・VIX変化・ドル円)
方向     = ±0.2%以内→横ばい / ±0.8%以上→強上昇・強下落
「主な背景」= S&P500の符号(上昇/下落)+ ドル円の符号(円安/円高)+ VIXが1pt以上動いたか
```

## 3. 予想の作り方による的中率(1,409日・同じ判定)

| 作り方 | 方向的中 | 平均誤差 |
|---|---|---|
| 先物ギャップだけ | 74.0% | 0.38% |
| 米国指標の回帰だけ | 58.8% | 0.41% |

→ 正しい先物データを使えば、今の作り方でも **約73%** 当たる設計。回帰を混ぜると誤差は小さくなるが、方向の的中はわずかに下がる。

## 4. それなのに直近29日の実績が5割を切った理由

(確定後の日足で「実際の寄り」を取り直して集計。記録値の誤りは6章参照)

同じ29日について、ダッシュボードの予想は **45%(13日)**、**先物の終値(前夜の米国取引終了時点)をそのまま使っていれば76%(22日)** 当たっていた。

外れた16日の内訳:

| 理由 | 日数 | 例 |
|---|---|---|
| **先物終値は当たっていたのに、予想が横ばい/逆向きになった** | **10** | 10/9:先物−0.89% → 予想+0.03%(横ばい)→ 実際−0.57%。8/20:先物+1.01% → 予想−0.87% → 実際+0.62% |
| 実際は小動き(±0.2%前後) | 4 | 10/6、10/7、8/24、8/28 |
| 先物も外れた(米国引け後〜寄りまでのニュース) | 2 | 8/26、9/29 |

原因は6章の「実行時刻」。回帰モデルが寄り付きではなく翌日の終値→終値の騰落で学習されている点も精度を下げる要因だが、影響は小さい。

## 5. 改善案

| # | 何を | どう変える | 期待 |
|---|---|---|---|
| 1 | 先物の取得 | 実行時点の5分足ではなく、**前夜の米国取引終了時点の終値(日足)**を使う。取得値と時刻を履歴に保存して検証できるようにする | 直近29日で 48%→約69%、長期で約73〜75% |
| 2 | 合成の重み | 先物0.7→**0.9**、回帰0.3→0.1 | 方向的中 +1〜2pt |
| 3 | 回帰モデル | 目的変数を**寄り付きギャップ**に、特徴量を S&P・NASDAQ・SOX・VIX に(ドル円は外す) | 回帰単体の精度改善 |
| 4 | 「主な背景」の要約 | 符号だけで円安/円高を挙げるのをやめ、**寄りへの寄与が大きい順**に表示(例:「先物−0.9%、SOX−3.4%(半導体安)、VIX+1.8」)。小さな動き(S&P±0.2%未満など)は挙げない | 要因の要約が実態と一致 |
| 5 | 寄り付き後の示唆 | 先物ギャップの向きは日中も続きやすい(相関+0.36)ことを、買い候補の判断材料として表示 | 当日の売買判断の補助 |

## 6. 根本原因:朝の処理が寄り付き後に動いていた

GitHub Actions の実行記録(公開API)を確認したところ、06:30〜07:50 に予定した5回の実行が**毎回2.5〜4時間遅れて 9:03〜12:11 に起動**していた(10/5〜10/14 の全日)。寄り付き後に動くと:

1. **予想が潰れる**:日経平均の「前日終値」として**当日の取引中の値**を拾い、先物も取引時間中の値になるため、先物ギャップがほぼ0 → 予想が横ばい付近に寄る(10/9 の +0.03% など)。
2. **「実際の寄り」の記録が誤る**:取引途中の日足から寄りを記録しており、**29日中8日**が確定値と0.3%超ずれていた(10/2:記録+2.34% → 確定−0.93%)。
3. 通知が寄り付き後に届くため、寄りで買う運用自体が成り立たない。

## 7. 実装した改善(同日)

| # | 内容 | 検証 |
|---|---|---|
| A | **いつ実行しても同じ結果になる計算**:日経平均・先物(NKD=F優先)・SOX等は「予想する日より前に確定した終値」だけを使う。日付は日本時間で扱う | 新コードで直近5日を再計算:旧ロジックが外した 10/8・10/9・10/13・10/14 の方向がすべて的中(10/7 は小動きで外れ) |
| B | **実際の寄りの記録を修正**:当日分は朝に記録しない。過去日は毎回確定値で上書き | 誤記録8日のうち過去分7日が確定値に修正されることを確認(当日分は翌朝に確定値が入る) |
| C | **9時前に届くよう予定を追加**:03:17〜05:47 にも実行予定を入れ、遅延込みで 06〜08時台に着地させる。06:10 より前に起動した回は米国の引け前なので何もせず後続に任せる。9時を過ぎた場合は通知の先頭に「⚠️配信遅延」を表示 | 翌営業日以降の着信時刻で確認 |
| D | 先物の重み 0.7 → **0.9** | 長期の方向的中 73.2% → 74.7% |
| E | **「主な背景」を寄りへの影響順に**:日経先物 → SOX(±1%以上)→ NASDAQ・S&P500(±0.5%以上)→ VIX(±1pt以上)。ドル円は表示しない | 例:「主な背景: 日経先物 +0.68%、米国株は小動き。」 |

見送り:回帰モデルの作り直し(先物の重みが0.9になり影響が小さいため)。
分単位で確実に9時前に届けたい場合は、外部のcronサービスからGitHub APIで起動する方法がある(GitHubの個人アクセストークンの作成が必要)。

## 留意点
- 米国側の指標は日足終値で揃えている。ドル円は日足の区切りの都合で、寄りの直前までの動きを一部含む。
- 「先物だけで74%」は長期平均。米国引け後〜東京寄りまでのニュース(例:10/14)は、どの方法でも拾えない。
